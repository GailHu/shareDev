# 文档 → 报告编制包（doc-report-kit）

将**任意完整样本文档**解析为一套可重复生成同类文档的编制包。不写成稿引擎；产出结构、资料表与约束 Prompt。

## 何时启用

- 用户丢入一份或多份报告，要求分析结构 / 拆解章节 / 复刻同类报告
- 要求产出：信息收集表、模块 prompt、意图调用说明、结构化模版
- 关键词：报告 SOP、模块化提示词、资料收集表、意图路由、占位符模版

## 强制交付物（缺一不可）

在用户指定目录（默认当前工作区根目录或用户给出的输出目录）创建：

```text
{报告简称}/
├── {报告简称}信息收集表.html          # 左侧目录 + 分组表单 + 导出/导入 JSON
├── 意图调用说明.md                    # 意图路由 → 模块 Prompt 调用说明书
├── 报告模版/
│   ├── 00_结构拆解与编制资料条件.md   # 模块表 + 每模块所需资料 + 依赖
│   └── {报告简称}_结构化模版.md       # {{占位符}} 全文骨架
└── 模块提示词/
    ├── 00_意图路由.md
    ├── 01_{模块名}_{module_id}.md
    └── …按文档真实章节编号
```

命名：`{报告简称}` 取文档主标题浓缩（去日期/公司后缀噪音），中文可接受。

详细字段与文件骨架见 [reference.md](reference.md)。

## 工作流（必须按序）

### 0. 确认范围

- 输入路径：单份或多份样本（多份先做**共核结构**，差异记为分支参数，如行业/模板变体）
- 输出目录：用户未指定则用工作区下新建 `{报告简称}/`
- 若样本不可读（扫描版 PDF 无文字）：先说明限制，能 OCR 则 OCR，否则基于可见目录/用户补充继续

### 1. 提取与对比

1. 提取全文或至少：封面、目录、各章标题、代表性正文段、表格列头
2. 列出一级/二级标题树；标注：填空 / 叙述 / 评分表 / 附件占位
3. 多样本时输出差异表（章节有无、标题别名、评分体系、独有附件章）
4. 选定**主干模板**（样本最完整的一套）；其余作 `variant` 分支，写入拆解文档与收集表切换项

### 2. 定义模块（SOP 原子单元）

每个模块必须有：

| 字段 | 含义 |
|------|------|
| `module_id` | 短英文蛇形，如 `cover`、`ch01`、`ch04` |
| 名称 | 中文章节名 |
| 特征 | 填空 / 叙述 / 表格评分 / 附件 |
| 标准输出结构 | 标题层级、表头、编号规则（硬约束） |
| 必填输入 | 资料字段列表 |
| 依赖 | 如「问题章依赖评分扣分项」 |
| 禁止项 | 禁止虚构、禁止改标准原文等 |

模块粒度：以可独立生成/修改为准（通常一级章 + 封面/前言/目录）。

### 3. 产出四类文件

并行编写亦可，但逻辑上先拆解文档 → 模版与提示词对齐 module_id → 收集表字段与 JSON 键对齐 → 最后写意图调用说明。

#### 3.1 `报告模版/00_结构拆解与编制资料条件.md`

含：总体结构图或目录树、模块总表、编制前置条件、**分模块资料清单**、依赖关系、产物路径对照。

#### 3.2 `报告模版/{报告简称}_结构化模版.md`

按主干模板写出全文骨架：

- 固定文案保留；可变处用 `{{field_name}}`
- AI 撰写区标 `【AI生成区】` 并注明对应 `module_id`
- 扫描件/图片标 `【附件】{{path}}`
- 文末或旁注写清 variant 分支差异（若有）

#### 3.3 `模块提示词/`

- `00_意图路由.md`：自然语言 → JSON（`action`, `modules`, `variant/industry`, `sync_dependent`, `notes`）；含说法映射与白名单
- 每模块一个文件，统一骨架：

```markdown
# 模块约束：{module_id}（{中文名}）
## 任务
## 输出结构（硬约束）
## 输入参数
## 依赖（若有）
## 禁止
## 自检
```

评分类模块必须写明：**标准条文/分值只许来自输入；模型只填自评/扣分说明/叙述性单元格**。  
问题整改类必须写明：**问题 ⊆ 上游扣分/问题清单，禁止编造**。

#### 3.4 `{报告简称}信息收集表.html`

单页自包含 HTML（可内联 CSS/JS）：

- **左侧目录**锚点跳转 + 滚动高亮；窄屏可顶栏化
- 按 `module_id` 分 section；`data-path` 与导出 JSON 键一致
- variant 切换显示/隐藏分支字段与模块
- 动态行：适用于「扣分项/问题项/人员列表」等
- **导出 JSON / 导入 JSON / 复制 JSON**
- 页脚指向同目录下模版与模块提示词、意图调用说明

JSON 根对象至少含：`variant`（或等价字段）+ 各 `module_id` 对象。

#### 3.5 根目录 `意图调用说明.md`

必须写清：

1. 产物地图（相对路径）
2. 工作流：填表 → 路由 → 逐模块调用 → 按模版组装
3. 意图路由调用方式（System/User）
4. 单模块调用模板（System=模块 md，User=JSON 片段+依赖）
5. `module_id` ↔ 提示词文件名 ↔ JSON 键 对照表
6. 依赖与强制生成顺序
7. 质量门禁清单

### 4. 收尾

- 向用户用中文给出目录树与「如何用一句话开始生成」
- 不要删用户原始样本，除非用户明确要求
- 不要编辑用户未要求的 plan 文件

## 解析原则

- **忠于样本结构**：章节名、表头、固定套话以样本为准，不擅自「优化」成另一文体
- **多样本求交**：主干取完整集；差异用分支，不捏造第三套
- **资料可采集**：收集表字段必须能从业务侧拿到；无法稳定获取的标可选
- **生成可约束**：每个 AI 模块都有硬结构 + 禁止项 + 自检
- **注释中文**：HTML/脚本注释用中文（若需要注释）

## 输入格式处理

| 类型 | 做法 |
|------|------|
| PDF | 优先 pypdf/pdfplumber 抽文本；乱码则 UTF-8 落盘再读 |
| DOCX | 抽段落与标题样式 |
| MD/TXT/HTML | 直接读 |
| 多文件 | 先各自目录树，再合并共核 |

## 质量门禁

- [ ] 四个交付物齐全且 module_id 三处对齐（模版 / 提示词 / 收集表 JSON）
- [ ] 意图路由白名单 = 实际模块集
- [ ] 有依赖的模块在拆解、提示词、意图说明中均写明
- [ ] 收集表可导出可导入；左侧目录可用
- [ ] 结构化模版可凭占位符人工填出一版骨架
