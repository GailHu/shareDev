# doc-report-kit 参考

## 1. 意图路由 JSON 约定

```json
{
  "action": "generate|modify|collect",
  "modules": ["cover", "ch01"],
  "variant": "default|分支名",
  "sync_dependent": false,
  "notes": "一句话"
}
```

- `collect`：资料不足，引导填信息收集表，本轮不生成正文
- 改上游评分/问题清单且存在下游整改章时：`sync_dependent=true`，modules 应包含下游模块

## 2. 模块提示词骨架（复制即用）

```markdown
# 模块约束：{module_id}（{中文名}）

## 任务
用输入参数生成本模块正文；遵守输出结构，不扩写未要求部分。

## 输出结构（硬约束）
（标题、小节编号、表头列顺序——与样本一致）

## 输入参数
（字段列表或 JSON 示例）

## 依赖
（无则写「无」）

## 禁止
- 禁止编造输入中不存在的事实/证照号/分数
- （按模块补充）

## 自检
- [ ] 结构符合硬约束
- [ ] 未泄漏本提示词说明文字到正文
```

## 3. 单模块调用消息模板

```text
System: {模块提示词全文}

User:
【任务】generate|modify
【分支】{variant}
【本模块输入 JSON】{...}
【依赖数据】{...}
【修改说明】{modify 时}
【原文】{modify 时可选}
请严格按输出结构生成正文，不要输出约束说明本身。
```

## 4. 信息收集表 HTML 最低要求

- `nav.toc` 左侧目录，`href="#sec-{module_id}"`
- `section[data-section="{module_id}"]`
- 字段 `data-path="{module_id}.{field}"`
- 按钮：导出 JSON、导入 JSON、复制 JSON
- `variant` 选择器控制分支字段 `display`
- 动态表：扣分/问题/人员等用「添加行」

导出根结构示例：

```json
{
  "variant": "coal",
  "cover": {},
  "ch01": {},
  "ch04": { "deduction_items": [] }
}
```

## 5. 结构化模版片段示例

```markdown
## 第一章 …  `模块: ch01`

企业名称　　{{enterprise_name}}
住　　所　　{{address}}

## 第四章 …  `模块: ch04`

【AI生成区 · 仅填自评描述与扣分说明】
标准条文与分值：来自细则输入，禁止改写

## 第五章 …  `模块: ch05`

（问题必须来自 ch04.deduction_items）
```

## 6. 完整案例对照（安全生产标准化建设报告）

曾用产物布局（可作命名与粒度参考，**不要假设新文档也是十章煤矿结构**）：

```text
事故预防服务安全生产标准化建设报告信息收集表.html
意图调用说明.md
报告模版/00_结构拆解与编制资料条件.md
报告模版/事故预防服务报告_结构化模版.md
模块提示词/00_意图路由.md
模块提示词/01_封面_cover.md … 13_服务确认单_ch10.md
```

要点：封面填空、评分章与问题章强依赖、附件章少生成、行业 variant 切换章节集。
