# prd-from-idea

一个 Agent Skill：把一句话想法、粗略点子或零散需求转成一份**可验收、可否决需求渗入、可追溯**的产品需求文档（PRD）。

## 它解决什么问题

想法和 PRD 之间的差距不是字数，是信息类别。想法通常只有 How（一个方案），缺 Why（真问题）、缺成功判据、缺边界。把想法直接扩写成文档，产出的是一份看起来完整、却无法验收、无法排期、无法用来拒绝需求渗入的废页。

这个技能只交付三样东西——**共识、判据、边界**，并用七条自检把住出口：

| 自检 | 缺失的后果 |
|------|------------|
| 可证伪 | "做完了"由谁嗓门大决定，测试无法设计 |
| 无歧义 | 三个人对同一句话干出三种实现 |
| 闭环 | 逆向、异常、超时、越权路径由开发各自发明 |
| **边界显式** | 实现期需求持续渗入，没有拒绝的依据 |
| 唯一真值 | 同一规则两处定义，改一处漏一处 |
| 可追溯 | 功能连不回任何目标，纯属堆功能 |
| 有优先级 | 砍范围时无从下手 |

## 安装

把 `prd-from-idea` 整个目录放到下面任一位置：

| 范围 | 路径 |
|------|------|
| 个人（所有项目可用） | `~/.cursor/skills/prd-from-idea/` |
| 项目（随仓库共享） | `<仓库根>/.cursor/skills/prd-from-idea/` |

Windows 的个人技能目录为 `C:\Users\<用户名>\.cursor\skills\`。

> 不要放进 `~/.cursor/skills-cursor/`，该目录由 Cursor 内置技能占用。

安装后重启或新开一个对话即可生效。

## 使用

**自动触发**：直接抛出想法并提出要求即可，例如

```
我想做一个能自动整理会议录音、输出待办事项的工具，帮我写份完整的 PRD
```

**显式调用**：在对话中点名 `prd-from-idea`。

产出文件名 `<项目名>-PRD-v0.1.md`，默认写入当前工作区根目录。

若不希望自动触发（避免随口聊想法就开始写文档），在 `SKILL.md` 的 frontmatter 中增加一行：

```yaml
disable-model-invocation: true
```

### 关于澄清提问

技能会在写作前**一次性**提出最多 7 个问题，每个问题自带默认假设。可以只回答其中几个，也可以直接说"按默认"。没回答的一律落进文档第 12 节「开放问题」，格式为「问题 + 影响范围 + 默认假设 + 需谁在何时确认」。**不会反复追问**，信息缺失不阻塞产出。

## 目录结构

```
prd-from-idea/
├── SKILL.md      # 主流程：八步工作法、三张扫描表与交付前自检
├── template.md   # PRD 骨架，共 13 章，按 S/M/L 档位标注必写项
└── README.md     # 本文件
```

## 工作流程概览

1. **把想法还原成问题** — 沿"表层想法 → 动机 → 现在怎么凑合 → 是否群体痛点"四层反推，并做伪需求识别
2. **判定规模档位** — S（一页纸）/ M（全量）/ L（全量 + 决策记录），不确定时取高一档
3. **一轮批量澄清** — 上限 7 问，每问带默认假设，只问一次
4. **先定成功判据，再写功能** — 北极星 + 输入指标 + **护栏指标**，每个都要写计算口径
5. **划边界** — 包含范围、**排除范围（附原因）**、MVP 四级分类、术语表
6. **展开功能，穷尽异常** — 主流程写完后过十项异常扫描表
7. **量化非功能需求** — 逐句消灭形容词，性能带分位数
8. **风险、依赖、决策记录** — 未知信息进开放问题，不静默假设

## 三张核心表

`SKILL.md` 的密度主要在三张可直接照着过一遍的表：

- **异常遗漏扫描表**（第 6 步，十项）— 逆向操作、空态、并发幂等、权限越界、历史数据、失败可见性、数量上限、时区、多端一致、依赖不可用。实践中这一步产出的条目常比主流程本身更多。
- **量化替换表**（第 7 步）— 把"加载要快""支持大量数据""及时通知"改写成带数字的要求。
- **PRD 与详细设计的边界表** — 表结构、接口路径、缓存策略一律不进 PRD，避免过早锁定实现、评审失焦。

## 与 tech-roadmap-from-prd 衔接

两个技能构成完整链条：

```
想法 --prd-from-idea--> PRD --tech-roadmap-from-prd--> 技术路线
```

为此 `prd-from-idea` 要求硬约束尽量写成**带数字、含「必须 / 禁止 / 不得 / 仅」的独立句子**，便于下游直接提取成编号约束（C1、C2……）。PRD 定稿后可直接接着说「根据这份 PRD 出一份技术路线」。

## 自定义

- 团队有固定的 PRD 规范时，改 `template.md` 的章节结构即可，`SKILL.md` 不用动。
- 领域固定（如只做 B 端后台、只做移动端）时，可在 `SKILL.md` 第 6 步的异常扫描表中补充该领域高频的遗漏项。
- 指标体系固定（如统一用 AARRR 或 HEART）时，可在第 4 步写明指标口径的来源表。
- 档位判据可按团队的回滚成本重新校准，`SKILL.md` 第 2 步的三行判据是唯一改动点。
